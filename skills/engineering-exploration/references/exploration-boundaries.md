# Exploration Boundaries

Use this reference when the user's request sits near the boundary between discussion, planning, and implementation.

## Stay In Exploration Mode

Stay in exploration mode when the user asks for:

- ideas, concepts, directions, or product shape
- requirements or scope clarification
- architecture or technical approach
- pros and cons
- feasibility
- naming, module boundaries, or constraints
- "how would we build this"
- "what should this include"
- "先聊", "先构思", "先探索", "先设计", "不要写代码", "不要修改"

Good responses in this mode usually produce clearer decisions, not file edits.

## Ask Before Implementing

Ask for confirmation when the user says:

- "可以按这个做"
- "这个方案不错"
- "差不多了"
- "下一步呢"
- "怎么开始"

These phrases show momentum but do not always authorize workspace changes. Ask a concise question such as:

"要我现在开始落地到文件里吗？"

## Implement Only With Clear Authorization

Implementation is allowed when the user explicitly asks to:

- create or edit files
- scaffold a project
- write code
- apply a plan
- run setup, build, migration, or deployment commands

Once implementation is authorized, follow the normal coding workflow: inspect the workspace, make scoped edits, verify, and report what changed.

## Response Patterns

For brainstorming:

"我会先把这个拆成几个可选方向，然后帮你选一个最轻量但有价值的版本。"

For design:

"这里可以从目标、约束、架构、接口、风险和测试几个角度来定方案。"

For ambiguous momentum:

"这个方案已经可以落地了。要我现在开始改文件实现，还是继续把设计细化一层？"
