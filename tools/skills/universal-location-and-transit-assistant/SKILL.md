# Universal Location & Transit Skill

在处理用户的地理和交通查询时，用户的表述可能非常口语化、模糊或缺失关键信息。你必须严格按照以下策略框架进行推理和工具调用，这能确保你聪明地理解需求，并彻底避免因过度调用 API 而触发 `max_steps` 限制。

## 阶段 1：语义理解、空间推断与地标解析
在调用任何地图工具前，先执行以下**四级空间解析策略**：

1. **时空状态考量 (Temporal & Spatial Context)**：
   - 获取当前系统的时间（如：深夜、早高峰）。如果用户有场景化需求（如“找吃的”），应结合时间因素调整搜索词（例如：若当前是深夜，应在搜索时偏向“夜宵/24小时”等关键词）。

2. **识别模糊代词与隐式位置 (Identify Pronouns & Location)**：
   - 检查用户输入是否包含指代性名词（如“我的学校”、“我家”）或缺失起点的查询（如“离我最近的地铁站”）。
   - **记忆检索**：如果包含代词，立刻调用 `MemorySearch`（或相关的 RAG 提取工具）去检索该代词对应的实际地址。
   - **兜底提问**：如果记忆库未命中，**绝对禁止**将代词直接传给外部 API。立刻停止调用并反问用户：“我似乎还没有记住您的学校在哪里，请问具体的地址是？”

3. **关键词泛化翻译 (Keyword Standardization)**：
   - 如果用户使用了非标准的生活口语（如“撸串”、“带娃”、“打发时间”），你必须在心里将其翻译为标准地图兴趣点（POI）分类（如“烧烤”、“游乐场/公园”、“咖啡厅/商场”），再将其作为参数传给后续搜索工具。

4. **标准地名与城市解析 (Geocoding & City Extraction)**：
   - 使用 `InputTips` 或 `Geocode` 获取起终点坐标时，**必须同时提取该地点所在的“城市名称（City）”**。这是后续可能进行公共交通（公交/地铁）路线规划的必需要素。

## 阶段 2：自适应搜索策略 (Adaptive Search Strategy)
根据用户的核心意图，选择以下执行路径：

**路径 A：周边综合探索（高宽容度展示）**
- **适用场景**：用户探索周边（“XX附近有什么好玩的/吃的/交通”）。
- **操作规范**：使用泛化后的关键词调用 `NearbySearch`。
- **输出要求**：不需要调用 `Route` 计算实际步行/驾车时间。直接按直线距离返回最近的几个选项，做口语化、体验导向的总结即可。

**路径 B：精准寻找“最近的 X”与路线规划（资源保护与防坑模式）**
- **适用场景**：用户寻找最近设施或比对通行方案。
- **操作规范**：
  1. 通过 `NearbySearch` 查找候选列表，**强制只截取直线距离最近的 Top 3**。
  2. 对这 3 个地点调用 `Route` 工具计算实际通勤距离（驾车/步行/公交）。注意：如果是公交规划，必须传入阶段 1 获取的城市名。
  3. **弹性步进校验（解决“隔江相望”坑点）**：比较这 3 次 `Route` 结果。如果发现实际通勤距离极其离谱（例如直线仅 100 米，但因河流/高架阻隔需要绕行 5 公里以上），则允许额外取直线距离第 4-6 名的地点再进行一次（仅限一次）路线比对。
  4. 选出实际通勤时间/距离的最优解并返回。**绝对禁止**进行无限制的循环计算。

## 阶段 3：优雅降级与兜底 (Graceful Degradation)
- 如果 `Geocode` 解析失败，或者 `NearbySearch` 没有任何返回：
  - **禁止**用相同参数反复重试。
  - 尝试扩大搜索半径（如将 Radius 从 1000 提升至 3000）或放宽限制条件重试一次。
  - 如果依然失败，立即停止并向用户报告：“抱歉，我未能准确找到该地点/周边设施，您可以提供更详细的地址或周边标志性建筑吗？”
